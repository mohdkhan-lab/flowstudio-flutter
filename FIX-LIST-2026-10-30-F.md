## Addendum 17 — v2.48.3 (4-Slot Sliding Window + Sequential Safe Background Download Pipeline)
Owner request: "4-4 karke video lagatar banta rahe... jab koi si bhi 1 video ban jaye (render complete), foran next prompt ko de de jis se 4 slots continuous chalte rahein... aur video background me safe and fast one-by-one download hoti rahe... dono kaam ek saath chalein."
- **4-Slot Sliding Window Concurrency**:
  - In `engine/flowAutomation.js`, when ANY 1 video tile completes rendering (`bestTile.isReady`), the engine instantly pre-captures the signed media URL and session cookies/User-Agent, enqueues the task into the dedicated background sequential download pipeline, and immediately returns to `workerPool`.
  - In `engine/workerPool.js`, `activeWorkerTasks` immediately removes the ready task (`t.completed && t.downloadEnqueued`), reducing active count from 4 to 3.
  - A 1-second DOM safety debounce is applied, and the worker immediately pops the next pending prompt and submits it to Flow (`submitPrompt`), keeping all 4 generation slots fully utilized with zero idle time.
- **Dedicated Sequential Background Download Pipeline (FIFO)**:
  - Download pipeline operates independently of Puppeteer page interactions: direct Node HTTP streaming fetch (`downloadFromCapturedStream`) runs using pre-captured cookies without touching `this.page`, eliminating DOM race conditions and navigation crashes.
  - Downloads are processed strictly one-by-one sequentially in FIFO order, preventing network throttling, socket exhaustion, and disk I/O contention.
  - Strict mapping of `promptIndex` to file name (`scene001.mp4`, `scene002.mp4`...) ensures perfectly ordered output even if renders finish out-of-order.
  - Every downloaded file is verified with `ffprobe` (> 50KB, valid video stream, `fs.fsyncSync`), updates SQLite DB, and emits UI completion events.
  - If direct fetch encounters an edge case, it safely falls back to retry without resubmitting prompts or deducting credits.
- **Windows Sleep Blocker (`engine/sleepBlocker.js`)**:
  - Automatically acquires `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` via Windows kernel32 at the start of generation and releases it upon batch completion, guaranteeing that Windows will not sleep or idle mid-run during long overnight batches.
- Version bumped to 2.48.3 across all 8 version files + smoke test.
